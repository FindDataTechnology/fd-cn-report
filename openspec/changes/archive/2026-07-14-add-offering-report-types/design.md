## Context

`fd-cn-report` extracts financial indicators from CN listed-company reports. The report
type is selected by the caller-supplied `form` argument on the extraction entry points
(`extract_indicators`, `extract_indicators_by_position`, `extract_indicators_batch` in
`indicators_client.py`), defaulting to `年度报告`. Rules carry a `report_type` (= DB
`document_type`); `_form_compatible(rule, form)` gates a rule against the requested form via
a substring test `key in rt` where `key = _FORM_COMPAT_KEY.get(form, form)`.

Current state (the "CN annual-report logic" this change mirrors):

- **Forms**: exactly four CN periodic forms - `年度报告 / 半年度报告 / 第一季度报告 /
  第三季度报告` - mapped by `_FORM_COMPAT_KEY` (in two places: `indicators_client.py:469`
  and `report_section_map.py:11`) to `年报 / 半年报 / 季报`. The `llm-indicator-extract`
  spec hard-caps the set at these four.
- **Section map**: `docs/report_section_map.json` is form-keyed (`年报 / 半年报 / 季报`),
  mapping each canonical section to alias lists. `report_section_map.candidates(form, key)`
  is consumed by `indicators_client._resolve_section` to locate a section in the parsed
  outline before extracting.
- **Rules**: `llm_rules` rows keyed by `(indicator, document_type)`. The same indicator can
  carry different rules per `document_type`. Generated by the `fd-cnreport-pdf-llm-rules-creator`
  skill (`--pdf <path> --document-type <type>`): splits the PDF by outline, one LLM call per
  chapter, pydantic-validated, upserted via `rules_db.upsert_llm_rule`.
- **Clients**: `cninfo_client` resolves the four periodic forms to `category_*_szsh` codes
  from `cninfo_categories.json` (group `定期报告`). The `融资` group already contains
  `首发` (`category_sf_szsh`, "IPO / prospectus (招股说明书)"). `hk_stock_client` already
  fetches HK annual-report filings (`get_hk_annual_report_filing`) and lists HKEX filings by
  title search (`list_hk_filings`).

Hard-coded annual-report assumptions that block the new types (found by exploration):

1. `_llm_extract_section` system prompt literally says "Chinese annual-report text" and
   "Return only the most recent year's (2023) value" - a hard-coded year.
2. `_resolve_via_akshare` hard-codes `target = f"{year}-12-31"` (assumes Dec-31 year-end;
   HK companies and prospectus historical periods do not all end Dec-31).
3. Heading / statement matchers (`_HEADING_RE`, `STATEMENT_TITLES`) target CN outline +
   statement names (第X章/节, 合并资产负债表); HK reports use 第X部/Section + IFRS statement
   names (綜合收益表, 財務狀況表).
4. `_form_compatible` is invoked **only** in `extract_indicators_by_position` (CSV path);
   the plain `extract_indicators` path runs every applicable rule regardless of `form`, so a
   prospectus rule would leak into an annual extraction today.
5. `make_report_id = sha1(source|company|year)` does not include `form`, so an annual report
   and a prospectus for the same company + year would collide in `report_documents`.

Constraints:

- `document_type` / `report_type` / `form` are runtime contracts (CLAUDE.md). Naming must be
  settled now; renames later are forbidden.
- Reuse the existing rules DB + generator skills; do not build a parallel rule store.
- The in-flight `industry-financial-report-rules` change introduces `cn/<industry>/<co_type>/<report_kind>`
  kebab naming for **industry-scoped** annual reports. The offering/HK types here are
  cross-industry, so they use the flat Chinese-form naming like the existing periodic forms.

## Goals / Non-Goals

**Goals:**

- Make `招股说明书`, `港股全球发售`, `港股年度报告` first-class report types: selectable via
  `form`, resolvable via section maps, and fetchable via the existing clients.
- Generate a baseline LLM-rule set for each type (the headline deliverable), persisted to
  `llm_rules`, mirroring how the annual-report rule set is structured.
- Remove the hard-coded annual-report assumptions that would mis-extract or crash on the new
  types.
- Keep the change spec-driven: one new capability (`offering-report-types`) + one modified
  capability (`llm-indicator-extract`).

**Non-Goals:**

- Script-rule derivation (`script_rules`) for the new types - follows via the existing
  `fd-cnreport-pdf-scripts-by-type-creator` skill in a later change.
- The `cn/<industry>/...` naming - owned by `industry-financial-report-rules`.
- Building crawlers that ingest every company's prospectus; only the fetch + extract path is
  generalized. Golden-corpus / regression smoke tests are a follow-up (mirrors the open
  tasks 4.3-4.5 / 5.1-5.2 of `industry-financial-report-rules`).
- Guaranteeing extraction quality for every prospectus layout; rules are iterative.

## Decisions

### Decision: Flat Chinese `form` / `document_type` names for the three new types

**Choice:**

| Report type | `form` (selector) | compat key (`_FORM_COMPAT_KEY`) | `document_type` | Source |
|---|---|---|---|---|
| CN 公开募股 prospectus | `招股说明书` | `招股说明书` | `招股说明书` | CNINFO `首发` (`category_sf_szsh`) |
| HK global-offering prospectus | `港股全球发售` | `港股全球发售` | `港股全球发售` | HKEX 披露易 |
| HK annual report | `港股年度报告` | `港股年度报告` | `港股年度报告` | HKEX 披露易 (existing annual fetch) |

The substring test `key in rt` then works naturally: a rule tagged `document_type="招股说明书"`
matches only `form="招股说明书"`; a `港股年度报告` rule matches only `form="港股年度报告"`;
none of the new rules match a periodic form, and no periodic rule (`年报/半年报/季报`) matches
a new form.

**Why:** Consistent with the existing periodic-form naming (flat Chinese tokens), and these
types are cross-industry so the `cn/<industry>/...` path does not apply. Distinct `港股`-
prefixed names prevent any collision with CN `年报`.

**Alternatives considered:**

- Reuse `年报` for HK annuals. Rejected: HK reports use IFRS + a different disclosure
  framework; conflating them would mix incompatible rules under one `document_type`.
- Kebab names (`hk-annual-report`). Rejected: breaks consistency with the existing Chinese
  `form` tokens and the `_FORM_COMPAT_KEY` substring model.

### Decision: Extend `docs/report_section_map.json` with three new form maps

**Choice:** Add top-level form keys `招股说明书`, `港股全球发售`, `港股年度报告`, each mapping
canonical prospectus/HK sections to alias lists (Simplified + Traditional + English). The
canonical sections per type:

- **招股说明书 / 全球发售 (prospectus)**: 发行概况, 风险因素, 发行人基本情况, 业务概况,
  募集资金运用, 财务会计信息, 管理层讨论与分析, 股本及股东, 董事监事高级管理人员,
  主要合同, 其他重要事项.
- **港股年度报告 (HK annual)**: reuses the annual-report canonical sections
  (主要会计数据, 管理层讨论与分析, 财务报表, 財務狀況表/綜合收益表/現金流量表, 风险管理,
  股东情况, 董事及高管, 分部信息, 股息) with Traditional/English aliases.

`report_section_map.candidates(form, section)` picks these up automatically once
`_FORM_COMPAT_KEY` maps the new `form` values to the new section-map keys.

**Why:** Section resolution is the existing mechanism; adding data (not code) keeps the
change small and the maps reviewable.

### Decision: Generate LLM rules per type with the existing `fd-cnreport-pdf-llm-rules-creator` skill

**Choice:** For each new `document_type`, run the whole-PDF generator over a representative
PDF, producing `llm_rules` rows. Each type has a declared **baseline indicator set** the
generated rules must cover:

- **招股说明书**: 发行价, 发行股数, 募集资金总额, 募集资金净额, 发行费用, 发行后总股本,
  募集资金投向(项目+金额), 补充流动资金, 营业收入(近3年), 净利润(近3年), 总资产, 净资产,
  经营活动现金流, 主要风险因素, 主营业务, 控股股东, 实际控制人, 主要股东持股, 董事人数.
- **港股全球发售**: 发售价, 发售股数, 募集资金总额, 募集资金净额, 超额配售权, 募集资金用途,
  营业收入, 净利润/全面收益, 总资产, 净资产, 主要风险因素, 主营业务, 基石投资者, 主要股东,
  董事人数.
- **港股年度报告**: 营业收入, 经营利润, 净利润/全面收益, 毛利, 总资产, 净资产, 经营活动现金流,
  每股股息, 主要股东持股, 董事人数.

Prospectus-specific indicators (发行价, 募集资金净额, 风险因素, 募集资金投向, 基石投资者)
use new `module` values (`offering`, `use_of_proceeds`, `risk_factors`, `corporate`).
`module` is a free `String(64)` grouped by `(module, subgroup)` in `_llm_extract_section`,
so new modules need no schema change.

**Why:** Reuses the validated generator + DB write path; `instruction`/`position` are
already plumbed through `LlmRuleModel` and persisted. The baseline set makes coverage
testable.

**Alternatives considered:**

- Hand-author rules in `indicator_rules.json`. Rejected: the JSON is a migration seed only,
  not the runtime source of truth; the skill is the supported authoring path.
- Generate from section excerpts (`fd-cnreport-llm-rules-creator`). Rejected for the first
  pass: prospectus structure is chapter-based, so the whole-PDF chapter splitter is a better
  fit. Excerpt-based generation remains useful for rule iteration.

### Decision: Generalize the four hard-coded annual-report assumptions

**Choice:**

1. `_llm_extract_section` system prompt is parameterized: take `period` (the requested
   year/period) and a report-type descriptor; drop the literal `"2023"` and the
   "Chinese annual-report text" framing. The prompt SHALL state the target period explicitly.
2. `_resolve_via_akshare` year-end target is derived from the report's fiscal year-end when
   available, falling back to Dec-31 only for CN annual/periodic forms.
3. Heading + statement matchers gain HK/prospectus patterns (第X部/Part/Section;
   綜合收益表/財務狀況表/綜合現金流量表; 招股章程/全球发售 section titles).
4. `make_report_id` includes `form`: `sha1(source|company|year|form)`.

**Why:** Without these, prospectus/HK extraction would return wrong periods, miss HK
sections, or collide on `report_id`.

### Decision: Apply `_form_compatible` in the plain `extract_indicators` path

**Choice:** Hoist the `_form_compatible(rule, form)` filter out of
`extract_indicators_by_position` into the shared rule-selection step used by both entry
points. Rules whose `report_type` does not include the form's compat key go to `skipped`
(`source_type: "form_filter"`).

**Why:** Required for correctness - prospectus and annual indicators are disjoint, so
running all applicable rules regardless of `form` would mix them.

**BREAKING:** callers of plain `extract_indicators` that relied on `form` being ignored may
now see previously-run rules in `skipped`. The annual-report path is largely unaffected
(most existing rules carry `年报/半年报/季报`, which matches `年报`).

### Decision: Wire clients to the new forms without new categories

**Choice:**

- `cninfo_client`: `resolve_category("招股说明书")` -> `category_sf_szsh`; `_form_from_title`
  recognizes 招股说明书 / 首发 titles. No change to `cninfo_categories.json` (`首发` already
  exists under `融资`).
- `hk_stock_client`: add `get_hk_prospectus_filing(stock_code, year=None)` that searches
  HKEX 披露易 for 全球发售 / 招股章程 filings, paralleling `get_hk_annual_report_filing`.

**Why:** Both sources already expose the documents; only the form->category/filing mapping
is new.

## Risks / Trade-offs

- **[BREAKING form-filter in the plain path]** -> Existing annual-extraction callers may see
  new `skipped` entries. Mitigation: run `test_cnreport.py` / `test_llm_indicator_extract.py`
  and update assertions; the annual path is mostly unaffected since existing rules carry
  `年报/半年报/季报`.
- **[LLM rule quality is PDF-dependent]** -> Generated rules reflect the representative PDF
  chosen per type. Mitigation: pick one well-structured PDF per type for the first pass;
  iterate with the excerpt-based skill; coverage is checked against the baseline set, not
  against perfect accuracy.
- **[HK IFRS vs CN GAAP statement-name mismatch]** -> HK statement names differ from CN.
  Mitigation: the new section-map aliases + extended statement matchers cover Traditional /
  IFRS names; non-matches land in `missing` rather than crashing.
- **[`instruction`/`position` are stored but unused at runtime]** -> The generated rules'
  `instruction` will not influence extraction until the prompt is wired to use it. This is
  out of scope here but noted as the natural follow-up; the rules are still correct because
  extraction is driven by section text + selector `position`, not `instruction`.
- **[Section-map aliases are best-effort]** -> A prospectus may use a section title not in
  the alias list. Mitigation: `candidates()` falls back to `[raw]`, and `_resolve_section`
  has statement + body-text fallbacks.

## Migration Plan

1. Land the `form` / `_FORM_COMPAT_KEY` / section-map / client changes (additive; no
   existing form behaves differently until `_form_compatible` is hoisted).
2. Hoist `_form_compatible` into the shared path; update affected tests.
3. Generate + persist the LLM rules for the three types (idempotent upserts by
   `(indicator, document_type)`).
4. Rollback: revert the code; the generated `llm_rules` rows are harmless (unselected by any
   periodic form) and can be deleted by `document_type IN (...)` if desired.
